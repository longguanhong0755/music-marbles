# 音乐弹珠 Music Marbles

把一首歌变成一条可以分享的弹珠轨道。音符落成横杆，弹珠以恒定速度穿过折叠路径，每次撞击保留音高的颜色；撞击只改变横杆颜色，不产生闪光、光圈或粒子。创建页可以上传本地音频，也可以直接搜索纯音乐曲库，或使用内置曲目。生成链接即可在线观看，也可以导出 9:16、16:9、1:1、4:5 四种比例的 MP4。每条新链接会分配一个随机种子，同一条链接重放和导出始终是同一张地图；观看页可以点「换一条路」重新生成。

轨道可以开启「墙壁」：弹珠活动的区域会连成一间四四方方、不规则的大房间，房间外和房间里的非活动区域铺满纯黑色墙块；背后是墙的碰撞横杆会贴墙，房间中间的横杆允许悬空，不会强行补一块假黑墙。画面背景支持纯黑和纯白两档，观看页的「背景」开关会立即生效并记住选择，视频导出沿用当前背景。

这个分支把原始的「重力 + 旋转木板」物理换成了直线、轴对齐的台球引擎：路径紧凑折叠，弹珠匀速前进，每根横杆只撞一次，撞点与音符时间一一对应。

## 纯静态部署

仓库保留纯静态路径：没有后端时只显示四首内置曲目，可以直接播放，也可以在浏览器内离线渲染并下载带音频的视频。上传、纯音乐曲库、10 分钟分享链接和服务端 MP4 封装需要在本机运行完整服务。网络曲库使用 Incompetech（Kevin MacLeod 的器乐作品，CC BY 4.0），不需要注册、代理或 API key。

## 快速开始

需要 Node.js 18+（在 22 上测试）、npm，以及 `PATH` 里的 `ffmpeg`。

```bash
npm install
npm start
# 打开 http://localhost:8080/
```

启动时终端会打印所有可用的局域网地址。手机或同一网络里的另一台机器可以直接打开这些地址。分享链接使用浏览器访问时的 host，因此在局域网地址下生成的链接也是局域网链接。

> 这是一个本地 / 局域网应用，没有登录、没有限流，上传内容会写入 `data/`。不要直接暴露到公网。

## 使用流程

1. **导入音频。** 支持 MP3、WAV、M4A、AAC、OGG、OPUS、FLAC，最长 6 分钟，单文件 80 MB。浏览器在本地解码、重采样，Web Worker 找出音符起点和主要音高。12 秒左右的片段通常几秒内完成。
2. **或者搜索纯音乐曲库。** 切到「网络曲库」标签，曲库来自 [Incompetech](https://incompetech.com/music/royalty-free/music.html)，全部是 Kevin MacLeod 的器乐作品。服务端只保留 20 秒到 6 分钟、标题和描述里没有 vocal / lyrics / singer 等字样的曲目；可以输入曲名、乐器或情绪（支持钢琴、古筝、二胡、国风、电影等中文关键词，服务端先翻译成英文再搜索）。每页 10 首，点「使用」选中后，生成时由本机服务端代理下载音频，再走和本地上传完全相同的解码、重采样、音符识别和上传流程。观看页会标注作者、授权和 Incompetech 来源。搜索和下载需要联网，令牌 30 分钟有效。
3. **或者选一首内置曲目。** 切到「内置曲目」标签，四首原项目曲库作品（土耳其进行曲、山魔王的宫殿、演艺人、糖梅仙子之舞）。内置曲目永久保留。
4. **选择是否开启墙壁。** 创建页的「墙壁」开关默认开启。开启后，每段弹道会打开一个横平竖直的矩形房间格，所有格子连成一间不规则的大房间，房间外铺满 48 单位见方的纯黑墙块。背后确实是墙的横杆会贴墙，并用 1 单位重叠封住蓝缝；房间中间、背后没有墙的横杆可以悬空，不会强行补一块看起来像墙的黑色方块。这个选择会写进分享链接，观看页和视频导出沿用同一设置。在链接后加 `&walls=0` 或 `&walls=1` 可以临时覆盖。
5. **生成链接。** 每次生成会分配一个随机地图种子并写进链接；上传曲目的种子同时保存在服务器，旧的无种子链接保持原来的确定性地图。音频会被裁剪到合适长度并转成 192 kbps MP3，与音符列表一起保存。链接打开的是 `/watch.html?id=<id>`；旧的 `/watch/<id>` 会 302 跳到新地址。观看页播放栏的「换一条路」会生成新种子、更新地址栏并重建地图，分享按钮复制的新链接沿用这张地图。
6. **观看或导出。** 观看页用独立的高精度时钟驱动弹珠，音频只跟随画面，不会因为浏览器暂停音频而卡住。开头 1 秒是静音加速段：弹珠从静止开始，以 400 units/s² 加速，在音乐开始的瞬间达到恒定的 400 units/s。播放栏下方的「背景」开关可以在纯黑和纯白之间切换；选择写入 `localStorage`，并同步到地址栏的 `bg=white` / `bg=black` 参数，分享或导出时沿用。

## 10 分钟保留

上传生成的轨道和导出的视频都只保留 **10 分钟**：

- 创建后 10 分钟自动删除；服务端每 10 秒清扫一次，访问过期 API 或媒体地址时也会立即删除。
- 观看页有倒计时。点击「延长 10 分钟」会把过期时间重置为当前时间 + 10 分钟。
- 过期后页面会显示「链接已过期」，播放、下载和延长都会禁用。
- 内置曲目不受影响，永久保留。

可以用环境变量调整保留时间（单位毫秒，最低 60 秒）：

```bash
CONTENT_TTL_MS=60000 npm start
```

## 纯音乐曲库

创建页的「网络曲库」接入 [Incompetech](https://incompetech.com/music/royalty-free/music.html) 的公开目录 `pieces.json`。不需要账号、API key 或代理：

- 服务端启动后在后台读取目录，过滤掉 20 秒以下、6 分钟以上，以及标题、乐器或描述里带 vocal / vocals / singer / lyrics / spoken / rap 的曲目，内存缓存 12 小时。目录目前有 1300 多首可用器乐。
- 搜索在本地完成。中文乐器/情绪词先翻译成英文：`钢琴→piano`、`古筝→guzheng`、`二胡→erhu`、`琵琶→pipa`、`国风→chinese`、`电影→cinematic` 等；多个关键词需要同时命中。
- 每页 10 首，点「加载更多」继续翻页；标题匹配优先于乐器、情绪和流派匹配。
- `GET /api/source/search?q=<关键词>&page=<页码>`：返回来源信息、总数、是否还有下一页和曲目列表，每首曲目带一个 30 分钟有效期的音频令牌。
- `GET /api/source/audio?token=<令牌>`：校验 HMAC 签名、有效期和 URL 白名单后代理音频流，支持 Range 请求，预览和导入共用。只允许 `incompetech.com` 的 `/music/royalty-free/mp3-royaltyfree/` 路径，客户端不能拿任意 URL 让服务器抓取。
- 音频不落盘，单曲上限 80 MB；上游超时、返回网页或不可播放时，接口返回明确的错误，页面提示换一首或稍后再试。
- 选中网络曲目后，点「下载并生成」会下载音频，按本地上传同一条路径解码、识别、生成轨道；服务器保存的来源信息会显示在观看页顶部。
- 曲目按 **CC BY 4.0** 授权。公开分享时请保留 `Kevin MacLeod (incompetech.com)` 署名。

纯静态部署没有服务端，只显示「内置曲目」。

## 视频导出

观看页点击「下载视频」，选择比例：

| 比例 | 分辨率 | 常见用途 |
| --- | --- | --- |
| 9:16 | 1080 × 1920 | 抖音 / Reels |
| 16:9 | 1920 × 1080 | YouTube |
| 1:1 | 1080 × 1080 | 信息流 |
| 4:5 | 1080 × 1350 | 竖版信息流 |

弹窗里的 **「快速导出（720p）」** 默认关闭。勾选后按短边 720 输出（9:16 → 720 × 1280，16:9 → 1280 × 720，1:1 → 720 × 720，4:5 → 720 × 900），码率从 6 Mbps 降到 3 Mbps，帧率仍是 30 fps；编码更快，文件大约小一半。选择会被记住。

导出优先走 **WebCodecs 离线渲染**：在内存中逐帧渲染并编码，不再等待实时播放。横杆使用预渲染 sprite，避免每帧重复构造路径和 `shadowBlur`；编码队列按 `encodeQueueSize` 节流，不再每 4 秒强制排空一次。浏览器支持 H.264 硬件编码时会显式启用硬件加速；没有硬件编码时使用软件编码，画面仍然是完整的 30 fps。弹窗会显示当前检测到的编码能力，建议软件编码时开启快速导出。

只有在浏览器完全不支持 WebCodecs 或 MP4 封装时，才会回退到 `MediaRecorder` 实时录制。服务端处理有几条快路径：

- 浏览器支持 AAC 编码时，浏览器直接产出完整的 H.264 + AAC MP4：本地文件立刻可下载，分享副本在后台按 `muxed=1` 上传，服务端只做流拷贝（`-c copy` + faststart），不重新编码音频。
- 浏览器只有 Opus 编码时，仍然上传无声视频（`offline=1`），由服务端把原曲 AAC 音频封装进去，避免 QuickTime / Safari 把 Opus-in-MP4 当成无声视频。
- 输入已经是 H.264/AAC MP4 时，服务端直接 remux，不重新编码视频。
- 输入是 WebM/VP9 或其他编码时，服务端转成 H.264/AAC MP4；硬件编码器会先做一次极短的可用性探测，避免整条转码跑到最后才失败。

所有导出都是 30 fps，并使用与观看页相同的墙壁和背景设置。完整服务模式下导出的 MP4 同样保留 10 分钟。纯静态部署没有服务端，会在浏览器内直接生成带音频的 H.264 MP4：优先使用 AAC（QuickTime / Safari 兼容），浏览器没有 AAC 编码器时退回 Opus；两者都不可用才回退到实时录制（MP4 或 WebM，取决于浏览器）。

## 工作原理

- `scripts/engine.js`：构建紧凑折叠路径，运行恒定速度模拟。每根横杆按音符顺序、在对应时间被撞一次。种子会扰动 DFS 的候选顺序并可选镜像整张地图；种子 0 保持原来的确定性布局。
- `scripts/onset-worker.js`：无依赖的谱通量起点检测 + FFT 峰值取音高。它追求速度，不是完整的复音转谱模型；密集混音会得到艺术化近似。
- `scripts/scene.js`：把同一个场景渲染到任意尺寸的画布，屏幕播放和导出共用。横杆使用按音高/方向/背景缓存的 sprite，避免每帧重复路径和阴影计算。纯白背景是真正的纯白填充，不画星空、渐变或暗角；未命中的横杆在白色房间里带一圈深色描边，在黑色墙壁上仍然可见。撞击只换颜色，不生成粒子或闪光。
- `scripts/walls.js`：墙壁图层。每段弹道生成一个轴对齐的矩形房间格（从入口横杆背面到出口横杆背面），所有格子取并集，形成一间横平竖直、不规则的大房间；房间外铺 48 单位纯黑墙块。横杆背面离房间边缘 2 单位的位置如果还是空地，说明它悬在房间中间，不画墙根；如果已经出房间，才画一截黑墙根并与横杆重叠 1 单位封住蓝缝。墙壁只影响画面，不参与碰撞和计时；开关随轨道设置传入，实时播放和两种导出路径共用。
- `scripts/landing.js`：上传、纯音乐曲库搜索、解码、重采样、识别、请求链接和内置曲目卡片。网络曲目和本地文件共用同一条分析链路。
- `scripts/watch.js`：播放、1 秒加速段、暂停/重播、换一条路、背景切换、10 分钟倒计时、延长、过期状态和视频导出。WebAudio 被浏览器挂起时会自动切到 `<audio>` 媒体播放，保证有声音；没有后端时自动读取 `builtins/manifest.json`，并在浏览器内直接生成带音频的 MP4。
- `favicon.svg` / `favicon-32.png` / `apple-touch-icon.png` / `site.webmanifest`：站点图标和安装清单。
- `.nojekyll` / 相对资源路径：同一套页面既能由 Express 在根路径提供，也能直接放到 GitHub Pages 的子路径下。
- `scripts/vendor/mp4-muxer.js`：浏览器端 MP4 封装（MIT，见同目录 LICENSE）。
- `server/index.js`：Express 服务，负责上传、纯音乐曲库路由、音频代理、轨道存储、音频裁剪/补静音、分享 URL、种子持久化、TTL 清扫和 ffmpeg 视频处理。
- `server/sources.js`：Incompetech 目录、纯器乐过滤、中文关键词翻译、HMAC 令牌、URL 白名单和内存缓存。
- `tools/verify_engine.js`：对每首内置 MIDI、多种子矩阵和 1 秒加速段做引擎校验。
- `tools/verify_sources.js`：离线校验中文关键词、目录过滤、搜索排序、URL 白名单和令牌篡改/过期/类型混淆。`npm test` 会同时运行两套测试。

旧的 Basic Pitch 路径（`scripts/transcribe-worker.js`、`scripts/dist/`）仍保留在仓库里做实验，但应用不会加载它，模型在 `vendor/basic-pitch/`。

### 内置曲目

内置曲库只保留原项目曲库的四首作品，清单里保留 `sourceId`、`source`、`license` 和 `sourceUrl`：

- **原项目曲库**：`music/music.js` 中来自 [AndrewB330/MusicMarbles](https://github.com/AndrewB330/MusicMarbles) 的公版作品 MIDI，四首：土耳其进行曲、山魔王的宫殿、演艺人、糖梅仙子之舞。

```bash
npm run build:builtins
# 只重建指定曲目
node tools/build_builtins.js sugar-plum
```

需要 Python 3 + NumPy 和 `ffmpeg`，会写入 `builtins/<slug>/{notes.json,score.json,audio.mp3}` 和 `builtins/manifest.json`。只重建部分曲目时，其余曲目的清单记录会保留。

### 验证

```bash
npm test
```

检查内容包括：横杆不重叠、都在场地内、路径与未命中的横杆保持间距、每个音符恰好命中一次、恒速成立、多种子布局可复现且彼此不同，以及 1 秒加速段在第一个音符的时间点到达。测试还会读取 `builtins/manifest.json`，直接校验浏览器实际加载的四首内置曲目；`tools/verify_sources.js` 不联网，校验中文关键词、Incompetech 目录的纯器乐/时长/文件名过滤、搜索排序、音频 URL 白名单，以及令牌篡改、过期、类型和来源混淆。

## 限制

- 歌曲最长 6 分钟、最多 1000 根可视横杆。密集轨道会合并音符，而不是静默丢弃。
- 地图由链接里的 `seed` 决定：同一条链接始终是同一张图；旧的无种子链接走种子 0 的原始确定性布局。观看页「换一条路」会写入新种子。
- 纯音乐曲库来自 Incompetech 的公开目录，需要能访问 `incompetech.com`；服务端只接受自己签发的 Incompetech 音频地址，不缓存音频。上游不可达或曲目不可播放时，页面会提示换一首或改用本地上传。公开分享时请保留 Kevin MacLeod 与 incompetech.com 署名。
- 服务端没有账号体系、限流或公网防护，只适合本机和可信局域网。
- 视频导出优先使用 WebCodecs 离线编码；硬件编码不可用时软件编码仍然可用，但长曲可能比实时播放更久。此时建议勾选「快速导出（720p）」。只有浏览器完全不支持 WebCodecs 时才回退到实时录制。
- 服务端 ffmpeg 转码是 CPU 密集型任务；如果机器支持 `h264_videotoolbox`、`h264_nvenc` 或 `h264_qsv`，会优先使用硬件编码。已封装好的 H.264 + AAC MP4 会走 `-c copy` 快路径。

## 原始项目

本项目 fork 自 [AndrewB330/MusicMarbles](https://github.com/AndrewB330/MusicMarbles)。原始项目用自动生成的地图和下落弹珠来演奏音乐。

原始引擎特点：

- 迭代式地图生成器
- C++ 物理引擎（原 WASM 引擎保留在仓库里作参考，本分支实际运行纯 JS 引擎）
- 原生 HTML5 Canvas
- 原版使用 Tone.js 生成声音
